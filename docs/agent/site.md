# Site (template)

Static Astro + React (ThemeToggle, MobileNav islands only). Base `/site` (GitHub Pages project site).

- `astro.config.mjs`: site URL, base (`/site`), prefetch on hover, sitemap filter (excludes `/tags/`, `/search/`, `/og/`), expressive-code themes (Catppuccin Latte/Macchiato with `.dark` selector)
- Prefetch: `prefetch: { defaultStrategy: "hover" }` (ClientRouter). Internal links fetch on hover only — nothing is prefetched on load; external links and `data-astro-prefetch="false"` are skipped.
- Islands: `ThemeToggle` hydrates `client:idle` and is persisted across view transitions; `MobileNav` hydrates `client:media="(max-width: 767px)"` — it matches its `md:hidden` visibility, so desktop never loads its JS.
- Font preloads (`@font-face` in `global.css`): self-hosted variable Inter + JetBrains Mono (WOFF2, `/assets/fonts/`)
- Theme: `global.css` — Catppuccin tokens (`:root` Latte / `.dark` Macchiato), `@theme inline`, `@custom-variant dark`, `@layer base`
- View transitions: `<ClientRouter />` in `main.astro` (client-side swaps + route announcer). `ThemeToggle` island is persisted (`transition:persist="theme-toggle"`); `MobileNav` is not — its `current` prop is per-page. A swap removes the `<html>` class and replaces the head, so the inline theme script re-applies theme and both `theme-color` metas on `astro:after-swap` (once-only guard; metas re-queried each call). `global.css` kills `::view-transition-*` animations under `prefers-reduced-motion` (its transition CSS is not injected into static builds, so the guard is ours).
- Print: `global.css` `@media print` — hides `header`/`footer`, mirrors the light palette over `.dark` (plus prose-invert + expressive-code overrides) so paper reads dark-on-white even from dark mode, appends absolute link URLs
- SEO: `src/lib/seo.ts` (`absolute()` base-prefixes URLs); `main.astro` head contract (canonical + OG + article meta + feed autodiscovery + font preloads + theme script + theme-color sync)
- RSS: full-text `/rss.xml` (`content:encoded` via `experimental_AstroContainer`); `/rss.xml` alias via `rss.xml.ts`
- JSON Feed: `/blog/feed.json` (version 1.1, `content_html` full text via `experimental_AstroContainer`); autodiscovered in head alongside RSS
- Markdown: Sätteri processor (Astro 7 default) + a `headingAnchors` hast visitor in `astro.config.mjs` — h2/h3 text is wrapped in a self-link to its heading id (plain until hover, mauve on hover); Astro's own `heading-ids` plugin adopts those ids, so TOC links match
- Blog index: paginated via `src/pages/blog/[...page].astro` (`pageSize: 2` → `/blog/2/` exists with 3 posts; `Page N of M`, rel prev/next, trailing-slash URLs); post pages get a CSS-only reading-progress bar (`animation-timeline: scroll(root)`, zero JS, `aria-hidden`, posts only)
- Sitemap: `/sitemap-index.xml` (auto); excludes `/tags/` (thin, `noindex, follow`), `/search/` (client-side results view) and `/og/` (generated assets)
- Search: Pagefind 1.5 Component UI at `/search` (`noindex`, out of the sitemap). Only blog posts are indexed (`data-pagefind-body` + `data-pagefind-meta="title"` on the post `article`/`h1`); `bun run build` / `build:ci` run `pagefind --site dist` after the Astro build, so `/pagefind/` exists only after a build (dev has no index). Result links get their base from `<pagefind-config base-url>`; result-template markup lives in `src/components/search/result-template.html` (`?raw` + `set:html`). `--pf-*` variables map to Catppuccin tokens in `global.css` on `:root:root` — doubled because pagefind's own stylesheet sets the same variables on `:root` and the ClientRouter appends fetched stylesheets after ours, so equal specificity lost our mapping after a client-side nav into `/search`; template colours are explicit because the component hosts reset inherited styles
- Build: `bun run build`; 29 pages (plus the generated `/pagefind/` index and 3 indexed posts); `astro check` must pass; `public/og.png` must exist (shared OG image for home/projects/other pages)
- OG images: one build-time PNG per post at `/og/blog/<id>.png` (`src/pages/og/blog/[slug].png.ts`, `getStaticPaths` over the blog collection). Satori lays out a 1200×630 Latte card (`#eff1f5`) with the mauve (`#c6a0f6`) accent bar, title in Inter, site name/date/tags in JetBrains Mono; `@resvg/resvg-js` rasterises it. Fonts are read from `src/assets/fonts/*.woff2` — variable fonts, so satori renders the regular instance. Static endpoint, no SSR. Posts pass it to the layout's `image`/`imageAlt` props; other pages keep `/og.png`. Excluded from the sitemap (`/og/` filter)
- Tooling: `bun run lint` (oxlint — `react` + `typescript` plugins, correctness category; also lints `.astro` scripts), `bun run format` / `format:check` (oxfmt, scope `ts/tsx/astro`; Tailwind class sorting built in for `.tsx` and `.astro`, wired to `global.css` stylesheet + `cn`/`cva`). Note: `docs/` and `learning/` feed Tailwind's scanner, so a docs-only token (e.g. bare `prose-invert`) can add a dead utility rule
- CI: `.github/workflows/ci.yml` runs on `pull_request` + `workflow_dispatch` with `contents: read`: checkout → setup-bun (`.bun-version`) → `bun install --frozen-lockfile` → lint → format check → `build:ci`. Its steps intentionally mirror deploy; there is no shared reusable workflow.
- Toolchain pin: `.bun-version` (repo root) holds the Bun version (currently `1.4.3`) and both workflows read it via `setup-bun`'s `bun-version-file`, so a bump is one file, not two workflows; `package.json` `engines.node` stays the Node floor.
- Deploy: `.github/workflows/deploy.yml` is a single `deploy` job (`timeout-minutes: 15`) — checkout → setup-bun (`.bun-version`) → `bun install --frozen-lockfile` → one `Lint and format check` step (`bun run lint` + `bun run format:check`) → `bun run build:ci` → `echo "$GITHUB_SHA" > dist/build.txt` → `actions/upload-pages-artifact@v5` (`dist`) → `actions/deploy-pages@v5` → live verification. `withastro/action` is gone, so the toolchain installs once; one job means one runner boot. Measured step costs on the runner: install ~3s, lint+format ~2s, type-check + build + Pagefind ~20s → ~40s per deploy. `build:ci` also runs Pagefind, so the artifact includes `dist/pagefind/`. Triggers: push to `main`, `workflow_dispatch`, and a weekly `schedule` self-heal (`17 4 * * 1`) that republishes `main` in case a push-triggered run was lost.
- Deploy guardrails: `concurrency: { group: pages, cancel-in-progress: false }` — GitHub's own Pages default, because cancelling can interrupt `deploy-pages` mid-publish and leave the site on a stale artifact. No `paths-ignore` (Tailwind scans `docs/`/`learning/`, so a docs-only push can change the built CSS) and no Bun install cache (restoring `~/.bun/install/cache` costs about what the 3s install does). Never add protection rules/reviewers to the `github-pages` environment: the job would wait for approval and deploys would stall.
- Deploy verification: the last step polls `"$page_url/build.txt"` (cache-busted with `run=$GITHUB_RUN_ID-$attempt`, 20 attempts × 15s) until it equals `github.sha`, then asserts `pagefind/pagefind.js` and `sitemap-index.xml` return 200. `deploy-pages` reports success before its CDN serves the artifact, so this is what proves the live site is actually this commit. On failure it prints the Actions/Pages status from `githubstatus.com` (an open incident is the usual cause) before exiting 1.

No Playwright verification scripts committed — checks are ad hoc (`grep` assertions against `dist/`).
